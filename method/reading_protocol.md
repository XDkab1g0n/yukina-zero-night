# 摘錄與原設定：何時回查，讀到哪裡

**v3｜2026-11-13**。摘要負責導覽，原文負責限定含義。讓寫手很快掌握人物，又能在關鍵判斷前找到依據；摘錄沒有收錄的事，不能視為不存在。

## 給寫手的三層資料

1. **人物核心**：簡短說清楚她在意什麼、如何與人相處、說話與選擇的傾向、同時存在的反差，以及本時期的邊界。既有欲望、玩心與關係溫度，也有能力限制，不只剩禁止事項。每項附來源小節，搭配少量傳達人物聲音的原文；例句不要求照用。
2. **本篇事實與原文**：只放這篇用到的時期、關係、身分、場域與情節依賴。能力機制、權限、記憶、保密與關鍵關係保留含條件與例外的原文小節；一般背景可簡述並連到來源。區分正典事實、本篇推論、新創與未定事項。
3. **回查路線**：列「出現什麼問題 → 哪個檔的哪節 → 已收錄／待讀」，再附 `source_guide.md` 作包外入口。標明未涵蓋的重大領域，讓寫手知道邊界，不必附整本目錄逼他讀完。

起步以幾千字的核心與相關摘錄為試行方向，不設必達比例或字數上限。需要完整語意就保留完整語意，無關部分不為湊覆蓋率放入；長篇、跨時期與多人主場可以自然擴大。

## 誰準備，如何補上沒想到要問的事

首次建立某時期的人物核心時，整理者完整讀該核心人物原檔與世界核心設定，再看資料導覽相關路線；配角有主場或關鍵選擇時，也理解其完整人物檔。主控找出故事成立所依賴的前提，尤其是誰知道身分、當時記得什麼、誰能下令、能力是否可行。先核實再定案。需獨立覆核時依 `LOOP.md` 採用 K 預審。

核心卡可在來源未變時重用，不必每篇重做。記錄覆蓋檔案與小節、來源 commit、檔案 SHA-256；來源更新就檢查受影響內容，不只把新版號貼上舊摘要。只讀部分就標部分，截斷輸出不算讀完。需要分段讀的原檔，確認讀到所需小節的末尾。

K 審稿者獨立讀對應時期核心人物原檔與世界核心設定，從**正文實際採用的設定**找資料，包含寫手沒回報的假設。不能只審包內事實。單視窗做不到獨立時，如實記為自審。

## 何時回去讀

| 寫作情境 | 動作與起始範圍 |
|---|---|
| 摘錄已有依據，適用條件沒變 | 繼續寫，不為確認而反覆讀 |
| 本篇新店、天氣、小道具、普通動作，不改核心事實 | 自主創作；有後續影響的新創記錄下來 |
| 決勝依賴能力／裝備、解局依賴制度、有人將得知隱藏身分 | 構思時查完整小節與限制、例外；保密另檢查目擊、記錄與後續可追溯資訊 |
| 配角有重要選擇、稱呼不確定、關係親疏影響反應 | 讀人物動機、關係與語氣小節；成為主場時擴至人物檔 |
| 回憶、失憶、年齡、裝備或認識誰跨時期 | 先定位時間，讀事件索引相關段與當期設定，不倒套現在篇 |
| 摘錄矛盾、條件省略、來源更新，推論跨多小節 | 沿權責核對主管檔相關整章，仍不清楚則整檔或交主控 |
| 改變核心人格／長期關係，或處理整段成長歷史 | 定大綱前讀相關人物整檔與涉及的時期資料 |
| 沒寫錯但人物扁平、缺靈感 | 自主探索欲望、生活與關係段落，有幫助再延伸 |

這是取用判斷，不是每幕必填表。只記實際回查與未解事項。

## 讀多少，以及何時停

搜尋先定位，再讀完整語意單位：從小節標題到下一個同級或更高標題；「上述」「除非」「另見」指向外部時補那段。數字、單句搜尋結果或單獨例子不能代替條件。

讀完能回答本次問題的適用人物、時期、做法、限制與後果，就停止擴讀；沒有相關項目不硬湊。答案依賴兩份文件就讀兩邊相關段，局部無法理解人格或歷史才擴至整檔。擴讀以問題為單位，不固定往前後抓幾百行，也不因讀了一檔便重讀全部設定。

例如「能否用某裝備解圍」先查模式與條件，不先重讀生平；「十五歲的她是否記得某事」要連同歷史索引與當期資料，不能拿十八歲摘要推斷。這些是回查示例，不替具體問題預設答案。

沒有依據時，分清「來源未定」與「自己尚未找到」。前者依 README 的新創權責處理，後者先查主管檔。核心身世、能力、正式制度或長期關係無法裁決時交主控，必要時請 Charles 決定，不憑空填成正典；可以先寫不受影響的段落。

## 本篇資料包模板

```markdown
# 本篇資料
來源版本：{commit；未提交變更另記 SHA-256}
適用：{時期、已定案的大綱、續寫停點}

## 人物核心
{欲望／性格反差／互動聲音／重要邊界；摘要附檔名與小節}

## 本篇會用的事實
{每項標：正典／推論／新創／未定；正典帶來源}
原文摘錄：{必要小節；可另附 context_pack_*.md}

## 回查路線與涵蓋邊界
{本篇觸發問題 → 主管檔與小節 → 已摘錄／待讀}
未涵蓋：{有影響的領域；沒有就明寫}
其他路線：source_guide.md

## 尚待釐清
{影響大綱的疑問先解；普通創作空間不列為阻塞}
```

`build_context_pack.py` 協助帶來源摘錄與分檔，不判斷涵蓋是否足夠。每檔 40,000 bytes 是讀取技術界線，不是寫手必讀量或文學規範。

## 摘錄工具用法（給資料整理者）

範圍檔每行四欄：`來源路徑|heading|完整標題文字（不含 #）|用途`；標題須唯一，包含其子節直到下一個同級或更高標題。也相容舊的 `來源路徑|起行|迄行|用途`，但行號易隨修訂移動，重建時要人工核對選取內容。

```text
python method/build_context_pack.py workshop/<工作夾>/pack_spec.txt workshop/<工作夾>
python method/build_context_pack.py --check workshop/<工作夾>
```

第一次產生會記錄實際來源雜湊、原文行號、標題與 HEAD，未提交變更以雜湊辨識；既有輸出不直接覆蓋，確認要重建才加 `--overwrite`。沿用前跑 `--check` 驗證來源與摘錄未變；這不驗證語意完整，也不替已修改的規格檔重新選材。標題改名或重複會報錯，超長小節按行分檔，單行超出讀取上限則報錯，請人工分次讀取原文。

# 寫手與審稿循環

**v5｜2026-11-27**。預設由一位寫手完成初稿，K 查原典與連續性，R 冷讀，原寫手修訂，主控順讀驗收。大綱交代局面與條件，寫手決定場面的發展與解法。

## 預設流程

1. **定大綱、查前提、備資料。** 主控固定來源版本，整理時期、開局、各方欲望與知情、篇幅和指定條件。自選題材時用 `idea_log.md` 比較近作的衝突與人物選擇。情節所依賴的能力、權限、身分、既有關係與所知，先回查主管原檔。已指定方向或明確授權主控自選並直接交正文時，主控自行定案。Charles 還在選題，或核對後必須改動他指定的核心方向時，交他決定。只為定案方向整理人物核心、客觀現況、必要原文與回查路線，詳見 `reading_protocol.md`。續寫沿用上一段全文與既有對帳，按新增依賴補讀。
2. **一位寫手交初稿。** 短篇以全文交稿，長篇續寫以完整敘事單位交稿。寫手在既定條件內決定視角、發展、場面與節奏。複雜走位、視線或物件狀態若會影響因果，寫完該場再於附註補簡短場面圖與必要對帳。主控把設定查核結果整理成客觀事實與原文，審核清單留在工作紀錄。
3. **平行審稿。** K、R 讀同一版完整初稿，各自提交意見。K 依正文實際採用的設定與前文查主管原檔，區分硬傷、合理省略與尚待裁決事項，優先補足能保住原構想的條件。R 第一輪只收到正文、必要前文與讀者背景，先交帶定位的冷讀軌跡。主控收到後才提供短版閱讀目標與適用的近作摘要，供同一位 R 完成審稿。模板見 `reader_prompt.md`。
4. **原寫手修訂，主控順讀驗收。** 主控合併有依據的錯誤、重大閱讀問題、可選偏好與值得保留的效果，交原寫手決定寫法。預設一輪修訂，由主控對照意見順讀修訂後的完整正文。按下表處理仍有實質影響的改動。主要問題解決、因果接上且保留原稿長處後交付。定稿入 `stories/`，標記篇內新創，並在 `idea_log.md` 簡記衝突如何發生及敵方知情。

## 何時調整派工

| 情況 | 做法 |
|---|---|
| 需要獨立核對會牽動整篇的前提 | 主控先回查。若仍有實質疑義，或判錯將迫使主線重寫且需要獨立覆核，寫前請 K 核對關鍵事實與漏摘。由主控修正大綱或補包，情節解法交寫手。寫後優先由原 K 接續，補查正文新增的依賴。 |
| 同一大綱有兩條值得比較的故事走法 | 按需派兩位寫手，各交約 150 字提案，並排看兩案會讓誰採取不同選擇、由誰改變局面、留下什麼後果。由主控或 Charles 選定，入選寫手接寫全文。出題層的多樣性可由主控先探索。 |
| 修訂牽動設定或閱讀效果 | 能力、權限、身分暴露、時序、核心關係或結局因果由 K 看受影響的前後場景。重要動機、視角、結構、高潮或收尾由 R 重讀相關完整場景，影響全篇時重讀全文。需要時兩邊都查。只改字句，由主控順讀。 |
| 單視窗或輕量小品 | 一稿，分兩次重讀做設定核對與閱讀自審，依相同原文回查原則執行。工作紀錄如實標為自審。 |
| 長篇續寫 | 讀上一段全文與既有帳本，較早內容按需補讀。帳本記時間錨點、位置、所知、傷勢、裝備、承諾與伏筆等會影響續寫的事實。按敘事單位審稿，完篇再看連續性與整體弧線。 |
| Charles 明確要求完整競稿 | 先定候選數與篇幅，以同一大綱、讀者背景及閱讀目標比較匿名全文。K 判正典硬傷能否修，R 比閱讀效果，依理由選稿。由入選原寫手修訂，保留其敘事結構，匿名對照留在私人工作區。 |

## 工作紀錄

主控派工只附該角色需要的模板、必要資料與來源。續寫可用 `continuity.md` 或該篇既有帳本。複雜篇章可將大綱、摘錄、正文、審稿與修訂記錄放在 `workshop/`，簡單篇章可合併記錄。定稿後依 README 保留續寫所需資料與具代表性的方法實驗。

實測時記可取得的分角色用量、前提錯誤是否造成重寫，以及修訂保住了哪段正文效果。歷史結果見 `iteration_log.md`。
